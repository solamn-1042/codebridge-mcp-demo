# CodeBridge 首轮评测任务集

## 固定条件

- 仓库：本项目 `CodeBridge`，Git commit 由评测执行人填写。
- 两组使用同一模型、模型参数、提示词、仓库提交和问题顺序。
- 基线组仅允许 DSH 原生工具；CodeBridge 组允许原生工具和 CodeBridge MCP 工具。
- 每题运行 3 次。没有真实运行的格子保持空白，不填推测值。
- 评分时按“判定要点”逐项核对；全部满足记 1，否则记 0，并在备注写出缺项。

## 任务与判定要点

| ID | 用户问题 | 判定要点 |
|---|---|---|
| T01 | 这个仓库是做什么的？ | 说明它是接入 DSH 的本地 MCP 服务，用于仓库接手、代码上下文定位、改动复核和固定检查。 |
| T02 | 这个 MCP 服务和 Cordis 插件提供哪些工具？ | 区分 7 个 MCP 工具与状态、启停、重连 3 个 Cordis 管理工具。 |
| T03 | 项目依赖了哪些 Python 包和版本？ | 回答 MCP SDK `2.3.0`、pytest `9.1.1`，依据 `requirements.txt`。 |
| T04 | 仓库概览工具读取内容有什么上限？ | README 摘要 3000 字符、顶层目录最多 40 项。 |
| T05 | 当前测试工具实际执行什么命令？最长运行多久？ | 使用当前 Python 解释器执行 `-m pytest -q`，超时 120 秒。 |
| T06 | 我让 Agent 运行 `deploy` 检查会发生什么？ | 返回 `CHECK_NOT_CONFIGURED`，允许名称只有 `test`，不执行任意 Shell 命令。 |
| T07 | CodeBridge 会不会编辑源代码？ | 没有编辑或 Git 写操作工具；pytest 会执行仓库代码，可能产生缓存和其他副作用，不是沙箱。 |
| T08 | MCP 服务要分析哪个目录？模型能否读取其他目录？ | 根目录来自 `CODEBRIDGE_REPO_ROOT`，模型只能给相对路径；说明绝对路径、父目录跳转和链接拒绝。 |
| T09 | 如何查看具体修改，而不是只有统计？ | 用 `change_summary` 定位文件，再用 `git_diff` 读取 patch，区分 staged/unstaged/all。 |
| T10 | 如何定位实现并提供代码证据？ | 用 `search_code` 返回路径与行号，再调用 `read_file` 读取范围；依据真实代码回答，说明截断和续读。 |

## 汇总口径

- 任务完成率：通过记录数 / 有效运行总数。
- 平均总工具调用数：每次运行的工具调用数求和 / 有效运行总数。
- 平均耗时：每次运行耗时求和 / 有效运行总数。
- 输入 Token：仅使用模型接口真实返回的 usage；若 UI/接口未提供则留空。
- 应用改进指标时同时给出任务数、运行次数、模型和仓库 commit。此任务集未跑完前不填写改善百分比。
